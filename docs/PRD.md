## 1. 프로젝트 개요

### 1.1 프로젝트명

**청기백기 색깔 테스트**

### 1.2 앱인토스 앱 이름 후보

앱인토스 콘솔 및 Granite 설정에서 사용할 앱 이름은 kebab-case를 사용한다.

```txt
cheonggi-baekgi-test
```

대안:

```txt
color-focus-test
color-stroop-test
```

### 1.3 한 줄 소개

글자의 뜻이 아니라 실제 글자 색깔을 빠르게 고르는 집중력 / 반응속도 테스트

### 1.4 서비스 설명

청기백기 색깔 테스트는 Toss 앱 안에서 가볍게 실행할 수 있는 앱인토스 미니앱이다.

사용자는 30초 동안 화면에 표시되는 색상 단어를 보고, 단어의 뜻이 아니라 실제 글자 색깔을 선택한다.

예를 들어 `빨강`이라는 글자가 파란색으로 표시되면 정답은 `빨강`이 아니라 `파랑`이다.

이 앱은 단순한 색상 선택 게임처럼 보이지만, 사용자는 글자의 의미와 실제 색상 사이의 충돌을 빠르게 구분해야 한다. 따라서 짧은 시간 안에 집중력, 반응속도, 인지 전환 능력, 실수율을 자연스럽게 측정할 수 있다.

### 1.5 핵심 컨셉

```txt
읽지 말고, 색깔을 고르세요.
```

### 1.6 서비스 목표

- Toss 앱 안에서 30초 안에 끝나는 초간단 테스트 경험 제공
- 사용자가 별도 설치나 회원가입 없이 바로 플레이할 수 있는 미니앱 제공
- 점수, 정답률, 평균 반응속도, 집중력 등급을 통해 재도전 욕구 유도
- 결과 공유를 통해 자연스러운 유입 확장
- Toss Ads 배너 광고와 리워드 광고를 활용한 수익화 구조 마련
- 앱인토스 검수 기준에 맞는 안정적이고 과하지 않은 UI 제공

### 1.7 개발 형태

- Granite 기반 React Native 앱인토스 미니앱
- `@apps-in-toss/framework` 사용
- 파일 기반 라우팅 사용
- Toss 앱 내부 실행을 전제로 설계
- Android / iOS 별도 스토어 출시 고려하지 않음
- 앱스토어 / 플레이스토어 심사 대응 문구 제거

## 2. 사용자 정의

### 2.1 메인 사용자

#### Toss 앱 사용자 중 짧은 테스트를 즐기는 사용자

- Toss 앱 안에서 가볍게 즐길 수 있는 테스트를 찾는 사용자
- 30초 이내에 결과를 보고 싶은 사용자
- 집중력, 반응속도, 순발력 테스트에 흥미가 있는 사용자
- 친구나 지인에게 결과를 공유하고 싶은 사용자

### 2.2 서브 사용자

#### 캐주얼 게임 선호 사용자

- 복잡한 조작보다 단순한 터치 게임을 선호함
- 점수 갱신형 플레이를 좋아함
- 결과 화면에서 다시 하기 버튼을 누를 가능성이 높음

#### 두뇌 테스트 관심 사용자

- 집중력, 두뇌 나이, 기억력, 순발력 같은 키워드에 관심 있음
- 게임보다 테스트 형식의 콘텐츠에 더 반응함
- 결과 등급과 해석 문구에 관심이 큼

### 2.3 사용자 니즈

| 사용자 니즈 | 설명 |
|---|---|
| 빠른 시작 | 긴 설명 없이 바로 테스트를 시작하고 싶다. |
| 쉬운 규칙 | 한 번 보면 바로 이해되는 게임을 원한다. |
| 짧은 플레이 | 30초 내외의 짧은 시간을 선호한다. |
| 명확한 결과 | 점수, 등급, 정답률, 반응속도를 바로 확인하고 싶다. |
| 재도전 욕구 | 이전보다 더 높은 점수를 얻고 싶다. |
| 공유 욕구 | 결과를 친구에게 보여주고 싶다. |

### 2.4 사용자 페르소나

#### 페르소나 A: 20대 Toss 사용자

- Toss 앱을 자주 사용함
- 짧은 테스트나 밈성 콘텐츠를 좋아함
- 결과 공유에 익숙함
- 회원가입 없는 즉시 플레이를 선호함

#### 페르소나 B: 30대 라이트 게임 사용자

- 복잡한 게임보다 단순한 점수 경쟁을 선호함
- 출퇴근, 대기 시간에 짧게 플레이함
- 광고를 보고 추가 결과를 확인하는 것에 거부감이 낮음

#### 페르소나 C: 40대 이상 두뇌 테스트 관심 사용자

- 집중력, 반응속도, 인지 테스트에 관심 있음
- 조작이 쉬운 앱을 선호함
- 점수보다 등급과 해석 문구를 더 중요하게 봄

## 3. 핵심 기능

### 3.1 테스트 시작

#### 설명

사용자는 홈 화면에서 테스트 규칙을 확인하고 `시작하기` 버튼을 눌러 테스트를 시작한다.

#### 요구사항

- 홈 화면에서 앱 이름과 핵심 규칙을 보여준다.
- 사용자는 로그인 없이 테스트를 시작할 수 있다.
- 시작하기 버튼을 누르면 테스트 화면으로 이동한다.
- 테스트 시작 전 예시 카드를 제공한다.
- 홈 화면 하단에는 배너 광고를 노출할 수 있다.

#### 예시 문구

```txt
글자의 뜻이 아니라 실제 색깔을 고르세요.

예: '빨강'이라는 글자가 파란색이면 정답은 파랑입니다.
```

---

### 3.2 색상 문제 생성

#### 설명

앱은 색상 단어와 실제 글자 색상을 조합하여 문제를 생성한다.

#### 색상 목록

```ts
type ColorKey = 'red' | 'blue' | 'yellow' | 'green';
```

#### 색상 라벨

| ColorKey | 화면 표시 | 권장 색상 |
|---|---|---|
| `red` | 빨강 | `#E53935` |
| `blue` | 파랑 | `#1E88E5` |
| `yellow` | 노랑 | `#F9A825` |
| `green` | 초록 | `#43A047` |

#### 문제 생성 규칙

- 화면에는 색상 단어가 표시된다.
- 단어의 의미와 실제 글자 색상은 서로 다를 수 있다.
- 정답은 단어의 의미가 아니라 실제 글자 색상이다.
- MVP에서는 항상 단어 의미와 실제 글자 색상을 다르게 생성한다.
- 같은 문제가 과도하게 반복되지 않도록 직전 문제와 동일 조합은 피한다.
- 사용자가 답변할 때마다 다음 문제를 즉시 생성한다.

#### 문제 예시

| 표시 단어 | 실제 글자 색상 | 정답 |
|---|---|---|
| 빨강 | 파랑 | 파랑 |
| 노랑 | 초록 | 초록 |
| 파랑 | 빨강 | 빨강 |
| 초록 | 노랑 | 노랑 |

---

### 3.3 색상 선택

#### 설명

사용자는 화면 하단의 색상 버튼 4개 중 실제 글자 색상과 일치하는 버튼을 선택한다.

#### 요구사항

- 색상 선택 버튼은 4개를 제공한다.
- 버튼 라벨은 `빨강`, `파랑`, `노랑`, `초록`으로 표시한다.
- 버튼에는 텍스트 라벨과 색상 포인트를 함께 표시한다.
- 색상만으로 구분하지 않는다.
- 버튼은 엄지손가락으로 누르기 쉬운 크기로 제공한다.
- 사용자가 버튼을 누르면 즉시 정답 여부를 판정한다.
- 정답 여부와 반응속도를 기록한다.
- 정답 / 오답 후 즉시 다음 문제를 표시한다.

#### 선택 버튼 예시

```txt
[빨강] [파랑]
[노랑] [초록]
```

### 3.4 제한 시간 테스트

#### 설명

MVP에서는 30초 동안 최대한 많은 문제를 푸는 방식으로 테스트를 진행한다.

#### 기본 설정

```ts
const DEFAULT_TEST_DURATION_MS = 30000;
```

#### 요구사항

- 테스트 시간은 기본 30초로 설정한다.
- 테스트 중 남은 시간을 표시한다.
- 시간이 종료되면 자동으로 결과 화면으로 이동한다.
- 테스트 중에는 광고를 표시하지 않는다.
- 테스트 중 화면 이동, 뒤로가기, 앱 백그라운드 전환에 대한 정책을 정의한다.

#### 시간 표시 방식

- 숫자 타이머
- TimerBar
- 숫자 타이머 + TimerBar 조합

### 3.5 점수 계산

#### 설명

사용자의 정답 수, 오답 수, 정답률, 평균 반응속도를 기반으로 최종 점수를 계산한다.

#### 기본 지표

| 지표 | 설명 |
|---|---|
| 최종 점수 | 테스트 결과를 대표하는 숫자 점수 |
| 정답 수 | 맞힌 문제 수 |
| 오답 수 | 틀린 문제 수 |
| 정답률 | 전체 응답 중 정답 비율 |
| 평균 반응속도 | 문제 표시 후 답변까지 걸린 평균 시간 |
| 가장 빠른 반응속도 | 가장 빠르게 선택한 시간 |
| 가장 느린 반응속도 | 가장 느리게 선택한 시간 |

#### MVP 점수 계산식

```txt
최종 점수 = 정답 수 * 100 - 오답 수 * 50
```

#### 보정 규칙

- 최종 점수가 0보다 작으면 0점으로 표시한다.
- 오답도 평균 반응속도 계산에 포함한다.
- 응답 수가 0인 경우 평균 반응속도는 `-`로 표시한다.

### 3.6 결과 등급 표시

#### 설명

최종 점수와 정답률을 바탕으로 집중력 등급을 표시한다.

#### 등급 타입

```ts
type ResultGrade = 'S' | 'A' | 'B' | 'C' | 'D';
```

#### 등급 기준 초안

| 등급 | 조건 예시 | 표시 문구 |
|---|---|---|
| S | 정답률 90% 이상, 점수 2000점 이상 | 놀라운 집중력이에요! |
| A | 정답률 80% 이상, 점수 1500점 이상 | 집중력이 꽤 좋아요. |
| B | 정답률 65% 이상, 점수 1000점 이상 | 무난한 집중력이에요. |
| C | 정답률 50% 이상 | 조금만 더 차분히 해보세요. |
| D | 그 외 | 천천히 다시 도전해보세요. |

#### 요구사항

- 결과 화면에는 등급을 가장 크게 표시한다.
- 낮은 등급도 부정적으로 표현하지 않는다.
- 결과 문구는 재도전을 유도하는 긍정적인 톤을 유지한다.

## 4. 게임 규칙

### 4.1 기본 규칙

```txt
글자의 뜻을 고르는 것이 아니라,
글자의 실제 색깔을 고르는 테스트입니다.
```

### 4.2 플레이 방식

1. 홈 화면에서 테스트 규칙을 확인한다.
2. `시작하기` 버튼을 누른다.
3. 화면 중앙에 색상 단어가 표시된다.
4. 단어는 특정 색상으로 칠해져 있다.
5. 사용자는 단어의 뜻이 아닌 실제 글자 색상을 선택한다.
6. 정답 / 오답과 반응속도가 기록된다.
7. 즉시 다음 문제가 표시된다.
8. 30초가 지나면 테스트가 종료된다.
9. 결과 화면에서 점수와 등급을 확인한다.
10. 다시 하거나 상세 분석을 확인한다.

### 4.3 정답 기준

정답은 항상 `textColor` 값이다.

```ts
type TestQuestion = {
  id: string;
  wordLabel: string;
  textColor: ColorKey;
  correctColor: ColorKey;
  shownAt: number;
};
```

```txt
correctColor = textColor
```

### 4.4 오답 처리

- 오답을 선택하면 오답 수를 증가시킨다.
- 오답도 반응속도 기록에 포함한다.
- 오답 후 테스트를 멈추지 않는다.
- 짧은 피드백 후 바로 다음 문제로 넘어간다.

### 4.5 테스트 종료 조건

다음 조건 중 하나에 해당하면 테스트를 종료한다.

- 제한 시간 30초 종료
- 사용자가 테스트를 중단함
- 앱이 백그라운드로 이동함

MVP에서는 제한 시간 종료만 필수 구현한다. 앱 백그라운드 이동 처리는 테스트 무효 또는 일시정지 중 하나로 정의할 수 있다.

## 5. 결과 및 분석

### 5.1 결과 화면 목적

사용자가 테스트 종료 후 자신의 성과를 빠르게 이해하고, 다시 도전하거나 상세 분석을 확인하도록 유도한다.

### 5.2 기본 결과 항목

| 항목 | 설명 |
|---|---|
| 집중력 등급 | S, A, B, C, D 중 하나 |
| 최종 점수 | 계산된 테스트 점수 |
| 정답률 | 전체 응답 중 정답 비율 |
| 평균 반응속도 | 평균 선택 시간 |
| 전체 문제 수 | 사용자가 푼 문제 수 |
| 정답 수 | 맞힌 문제 수 |
| 오답 수 | 틀린 문제 수 |
| 짧은 해석 | 결과에 대한 간단한 설명 |

### 5.3 결과 문구 예시

#### S 등급

```txt
놀라운 집중력이에요!
색상과 글자를 빠르게 구분하는 능력이 뛰어납니다.
```

#### A 등급

```txt
집중력이 꽤 좋아요.
빠른 속도로 정확하게 색상을 골랐습니다.
```

#### B 등급

```txt
무난한 집중력이에요.
조금만 더 빠르게 고르면 더 높은 점수를 받을 수 있어요.
```

#### C 등급

```txt
조금만 더 차분히 해보세요.
급하게 누르기보다 실제 색깔을 먼저 확인하는 것이 좋아요.
```

#### D 등급

```txt
처음엔 어려울 수 있어요.
천천히 실제 색깔을 보고 다시 도전해보세요.
```

### 5.4 상세 분석

상세 분석은 리워드 광고 시청 완료 후 제공한다.

#### 상세 분석 항목

- 가장 빠른 반응속도
- 가장 느린 반응속도
- 정답 / 오답 개수
- 정답률 해석
- 반응속도 해석
- 개선 팁

### 5.5 공유 기능

MVP에서는 단순 텍스트 공유만 제공한다.

#### 공유 문구 예시

```txt
청기백기 색깔 테스트 결과!
집중력 등급: A
점수: 1850점
정답률: 88%
평균 반응속도: 520ms
```

### 5.6 다시 하기

결과 화면에서 `다시 하기` 버튼을 누르면 새로운 테스트를 시작한다.

#### 요구사항

- 기존 테스트 결과는 초기화한다.
- 새로운 문제 목록을 생성한다.
- 테스트 화면으로 이동한다.
- MVP에서는 다시 하기 전에 전면 광고를 표시하지 않는다.

## 6. 광고 및 수익화

### 6.1 광고 전략

청기백기 색깔 테스트는 짧은 반복 플레이가 핵심이므로, 테스트 흐름을 방해하지 않는 광고 배치가 중요하다.

테스트 진행 중에는 광고를 표시하지 않는다. 광고는 홈 화면, 결과 화면, 상세 분석 진입 시점에만 배치한다.

### 6.2 앱인토스 광고 전제

- 배너 광고는 React Native에서 `InlineAd` 컴포넌트로 렌더링한다.
- 배너 광고는 Toss 앱 5.241.0 이상에서 지원되는 것으로 보고, 미지원 환경에 대한 예외 처리를 둔다.
- 전면형 / 보상형 광고는 `loadFullScreenAd`와 `showFullScreenAd`를 사용한다.
- 전면형과 보상형 광고는 광고 그룹 ID 기준으로 구분한다.
- 통합 광고는 Toss Ads와 Google AdMob을 환경에 맞게 자동 선택하는 구조를 전제로 한다.
- 보상형 광고의 리워드는 `userEarnedReward` 이벤트가 발생했을 때만 지급한다.

### 6.3 광고 종류

| 광고 종류 | MVP 사용 여부 | 앱인토스 API | 사용 위치 |
|---|---:|---|---|
| 배너 광고 | 사용 | `InlineAd` | HomeScreen, ResultScreen |
| 보상형 광고 | 사용 | `loadFullScreenAd`, `showFullScreenAd` | 상세 분석 보기 |
| 전면형 광고 | 제외 | `loadFullScreenAd`, `showFullScreenAd` | 2차 검토 |

### 6.4 배너 광고

#### 노출 위치

- HomeScreen 하단
- ResultScreen 하단

#### 요구사항

- TestScreen에는 배너 광고를 표시하지 않는다.
- 주요 CTA 버튼과 충분한 간격을 둔다.
- 광고 로딩 실패 시 레이아웃이 깨지지 않아야 한다.
- 광고 영역은 사용자의 터치 실수를 유도하지 않아야 한다.
- `InlineAd.isSupported` 또는 관련 지원 여부 체크 후 렌더링한다.
- 최상위 스크롤 컨테이너를 제어할 수 있으면 `IOScrollView`를 사용한다.
- `IOScrollView` 적용이 어려우면 `impressFallbackOnMount`를 사용한다.

#### 테스트 광고 ID

```txt
ait-ad-test-banner-id
```

---

### 6.5 보상형 광고

#### 사용 위치

- ResultScreen의 `상세 분석 보기` 버튼 클릭 시

#### 사용 흐름

```txt
ResultScreen 진입
→ 보상형 광고 미리 로드
→ 상세 분석 보기 클릭
→ showFullScreenAd 호출
→ userEarnedReward 이벤트 수신
→ DetailResultScreen 이동
```

#### 리워드 제공 항목

- 상세 결과 분석
- 가장 빠른 반응속도
- 가장 느린 반응속도
- 집중력 해석
- 개선 팁

#### 요구사항

- 광고는 화면 진입 시 미리 로드한다.
- 버튼 클릭 시점에 처음 로드하지 않는다.
- `loaded` 이벤트를 받은 뒤에만 광고 보기 버튼을 활성화한다.
- `userEarnedReward` 이벤트가 발생한 경우에만 상세 분석을 제공한다.
- `dismissed` 이벤트만으로는 상세 분석을 제공하지 않는다.
- 광고 시청 실패 또는 중단 시 상세 분석을 표시하지 않는다.
- 광고 실패 시 사용자에게 쉬운 안내 문구를 표시한다.
- 광고 표시 후에는 다음 광고를 다시 로드한다.
- 컴포넌트 언마운트 시 광고 콜백 등록을 해제한다.

#### 광고 실패 문구

```txt
광고를 불러오지 못했습니다.
잠시 후 다시 시도해 주세요.
```

### 6.6 전면형 광고

#### MVP 포함 여부

MVP에서는 제외한다.

#### 제외 이유

- 앱인토스 내부에서 첫 출시 검수와 사용자 경험을 안정적으로 가져가기 위함
- 테스트 시작/재도전 흐름을 방해하지 않기 위함
- MVP에서는 배너 + 보상형 광고만으로 수익화 검증 가능

#### 2차 검토 위치

- 테스트를 여러 번 반복한 뒤
- 결과 화면에서 다시 하기 버튼을 누른 시점
- 앱 재진입 후 일정 시간이 지난 경우

### 6.7 광고 UX 원칙

- 테스트 중에는 광고를 표시하지 않는다.
- 사용자가 문제를 풀 때 광고로 집중을 방해하지 않는다.
- 광고 버튼은 일반 CTA와 명확히 구분한다.
- 광고를 보기 전에 사용자가 무엇을 얻는지 설명한다.
- 광고 로딩 실패 시 앱이 멈춘 것처럼 보이면 안 된다.
- 광고 미지원 환경에서는 광고 영역을 숨기거나 대체 안내 없이 자연스럽게 제거한다.

### 6.8 광고 문구 예시

#### 상세 분석 보기

```txt
광고를 보고 상세 분석을 확인하세요.
정답률, 반응속도, 개선 팁을 볼 수 있어요.
```

#### 버튼 문구

```txt
광고 보고 상세 분석 보기
```

## 7. UI / UX 방향

### 7.1 플랫폼

- 앱인토스 전용 미니앱
- Granite 기반 React Native
- Toss 앱 내부 실행 전제
- Android / iOS 스토어 출시 고려하지 않음
- 앱인토스 샌드박스와 Toss 앱 환경에서 테스트

### 7.2 디자인 방향

- 게임처럼 가볍지만 너무 유치하지 않게 만든다.
- Toss 앱 안에서 자연스럽게 보이는 도구형 테스트로 만든다.
- 마케팅 랜딩 페이지처럼 과한 장식을 넣지 않는다.
- 색상 테스트 앱이므로 색상 대비와 가독성을 최우선으로 한다.
- 사용자는 화면을 보자마자 무엇을 해야 하는지 이해할 수 있어야 한다.
- 테스트 화면에서는 장식보다 문제 인식과 버튼 터치 편의성을 우선한다.

### 7.3 화면 톤

- MVP에서는 밝은 배경을 기본으로 한다.
- 주요 색상은 테스트 색상 자체가 담당한다.
- 브랜드 포인트 색상은 Toss Blue 계열을 최소한으로 사용한다.
- 결과 화면은 차분하지만 성취감이 느껴지도록 구성한다.
- 테스트 진행 중에는 사용자의 집중을 방해하는 색상, 장식, 애니메이션을 최소화한다.

### 7.4 금지 디자인

- 글래스모피즘 사용 금지
- 보라 / 인디고 중심의 AI 느낌 금지
- 네온 글로우 애니메이션 금지
- 배경에 블러 원형 오브젝트 금지
- 그라데이션 텍스트 금지
- `Powered by AI` 같은 불필요한 배지 금지
- 과도한 캐릭터 장식 금지
- 테스트 중 화면 흔들림, 과한 파티클 효과 금지
- 주요 버튼과 광고가 너무 가까이 붙는 배치 금지

### 8.3 HomeScreen

#### 목적

사용자가 테스트 규칙을 빠르게 이해하고 시작하게 한다.

#### 구성

- 앱 이름
  - `청기백기 색깔 테스트`
- 설명
  - `글자의 뜻이 아니라 실제 색깔을 고르세요.`
- 예시 카드
  - `'빨강'이라는 글자가 파란색이면 정답은 파랑입니다.`
- 시작하기 버튼
- 하단 배너 광고

#### 주요 CTA

```txt
시작하기
```

#### UI 요구사항

- 앱 이름은 화면 상단에 명확하게 표시한다.
- 설명 문구는 짧고 직관적으로 작성한다.
- 예시 카드는 테스트 규칙을 바로 이해할 수 있도록 시각적으로 보여준다.
- 시작하기 버튼은 한 손으로 누르기 쉬운 크기로 제공한다.
- 배너 광고는 시작하기 버튼과 충분한 간격을 둔다.

### 8.4 TestScreen

#### 목적

사용자가 제한 시간 동안 색상 정답을 선택한다.

#### 구성

- 상단
  - 남은 시간
  - 현재 점수
- 중앙
  - 색상 단어
- 하단
  - 색상 선택 버튼 4개

#### UI 요구사항

- 중앙 단어는 매우 크게 표시한다.
- 단어 위치는 고정한다.
- 선택 버튼은 엄지손가락으로 누르기 쉬운 크기여야 한다.
- 버튼 간 간격을 충분히 둔다.
- 테스트 진행 중 광고는 표시하지 않는다.
- 테스트 중에는 불필요한 안내 문구를 노출하지 않는다.
- 정답 / 오답 피드백은 짧고 즉각적으로 제공한다.
- 오답 시에도 흐름이 끊기지 않도록 다음 문제로 자연스럽게 넘어간다.

### 8.5 ResultScreen

#### 목적

- 집중력 등급
- 최종 점수
- 정답률
- 평균 반응속도
- 짧은 해석
- 다시 하기 버튼
- 상세 분석 보기 버튼
- 공유하기 버튼
- 하단 배너 광고

#### UI 요구사항

- 가장 중요한 결과인 집중력 등급과 점수를 먼저 보여준다.
- 정답률과 평균 반응속도는 카드 형태로 분리해 보여준다.
- 결과 해석은 짧고 긍정적인 문장으로 제공한다.
- 다시 하기 버튼은 가장 눈에 잘 띄는 CTA로 제공한다.
- 상세 분석 보기는 보상형 광고와 연결한다.
- 공유하기 버튼은 MVP에서 단순 텍스트 공유 방식으로 제공할 수 있다.
- 배너 광고는 결과 확인을 방해하지 않는 위치에 배치한다.

### 8.6 DetailResultScreen

#### 목적

#### 구성

- 전체 결과 요약
- 정답 / 오답 개수
- 평균 반응속도
- 가장 빠른 반응속도
- 가장 느린 반응속도
- 집중력 해석 문구
- 개선 팁
- 다시 하기 버튼

#### UI 요구사항

- 상세 분석은 과도하게 복잡한 차트 없이 텍스트와 간단한 카드 중심으로 제공한다.
- 사용자가 자신의 결과를 쉽게 이해할 수 있도록 쉬운 문장으로 작성한다.
- 결과를 부정적으로 표현하지 않는다.
- “다음에는 더 좋아질 수 있다”는 긍정적인 톤을 유지한다.

## 9. 컴포넌트 요구사항

### 9.1 ColorWordCard

#### 설명

현재 문제의 색상 단어를 표시하는 컴포넌트이다.

```ts
type ColorWordCardProps = {
  label: string;
  color: string;
};
```

#### 요구사항

- `label`은 화면에 표시할 색상 이름이다.
- `color`는 실제 텍스트 색상이다.
- 텍스트는 화면 중앙에 크게 표시한다.
- 고정된 위치에서 렌더링되어야 한다.
- 테스트 중 레이아웃이 흔들리지 않아야 한다.

---

### 9.2 ColorChoiceButton

#### 설명

사용자가 정답 색상을 선택하는 버튼이다.

```ts
type ColorChoiceButtonProps = {
  label: string;
  color: string;
  onPress: () => void;
  disabled?: boolean;
};
```

#### 요구사항

- `label`은 버튼에 표시할 색상 이름이다.
- `color`는 버튼의 시각적 색상 또는 포인트 색상으로 사용한다.
- `onPress`는 사용자가 버튼을 눌렀을 때 실행된다.
- `disabled`가 true이면 버튼 입력을 막는다.
- 버튼은 모바일에서 쉽게 누를 수 있는 크기여야 한다.
- 버튼 간 간격을 충분히 둔다.
- 색상만으로 구분하지 않고 텍스트 라벨도 함께 표시한다.

---

### 9.3 TimerBar

#### 설명

남은 시간을 시각적으로 보여주는 컴포넌트이다.

```ts
type TimerBarProps = {
  remainingMs: number;
  totalMs: number;
};
```

#### 요구사항

- `remainingMs`와 `totalMs`를 기준으로 진행률을 계산한다.
- 시간이 줄어들수록 바의 길이가 감소한다.
- 진행률은 부드럽게 줄어들어야 한다.
- 색상 변화가 있더라도 과하게 자극적이지 않아야 한다.
- 타이머 숫자와 함께 사용할 수 있다.

---

### 9.4 ResultSummary

#### 설명

결과 화면에서 점수, 등급, 반응속도, 정답률을 보여주는 컴포넌트이다.

```ts
type ResultSummaryProps = {
  score: number;
  grade: 'S' | 'A' | 'B' | 'C' | 'D';
  accuracy: number;
  averageReactionMs: number;
  totalQuestions: number;
  wrongCount: number;
};
```

#### 요구사항

- 점수와 등급을 가장 크게 표시한다.
- 정답률과 평균 반응속도를 명확하게 보여준다.
- 전체 문제 수와 오답 수를 함께 표시한다.
- 숫자는 사용자가 빠르게 이해할 수 있도록 단위와 함께 표시한다.

---

### 9.5 BannerAdSlot

#### 설명

앱인토스 배너 광고 영역을 표시하는 컴포넌트이다.

```ts
type BannerAdSlotProps = {
  placement: 'home_bottom' | 'result_bottom';
};
```

#### 요구사항

- 내부적으로 `InlineAd`를 사용한다.
- HomeScreen과 ResultScreen 하단에 표시한다.
- TestScreen에는 표시하지 않는다.
- 광고 로딩 실패 시 레이아웃이 깨지지 않아야 한다.
- 주요 CTA와 충분한 여백을 둔다.

---

### 9.6 RewardedAdButton

#### 설명

보상형 광고를 보고 상세 분석으로 이동하는 버튼이다.

```ts
type RewardedAdButtonProps = {
  adGroupId: string;
  disabled?: boolean;
  onReward: () => void;
  onError?: () => void;
};
```

#### 요구사항

- 화면 진입 시 광고를 미리 로드한다.
- 광고 로드 완료 전에는 버튼을 비활성화하거나 로딩 문구를 보여준다.
- `userEarnedReward` 이벤트 발생 시에만 `onReward`를 실행한다.
- `dismissed`만 발생한 경우에는 리워드를 지급하지 않는다.
- 컴포넌트 언마운트 시 콜백을 해제한다.

## 11. 앱인토스 개발 요구사항

### 11.1 프로젝트 스캐폴딩

- 기존 RN 프로젝트가 있더라도 앱인토스 동작을 위해 Granite 기반으로 스캐폴딩한다.
- 프로젝트명은 kebab-case를 사용한다.
- `@apps-in-toss/framework`를 설치한다.
- `ait init`으로 앱인토스 설정을 구성한다.
- `granite.config.ts`의 `appName`은 앱인토스 콘솔 앱 이름과 동일해야 한다.

### 11.2 권장 설정

```ts
import { appsInToss } from '@apps-in-toss/framework/plugins';
import { defineConfig } from '@granite-js/react-native/config';

export default defineConfig({
  appName: 'cheonggi-baekgi-test',
  plugins: [
    appsInToss({
      brand: {
        displayName: '청기백기 색깔 테스트',
        primaryColor: '#3182F6',
        icon: '',
      },
      permissions: [],
    }),
  ],
});
```

### 11.3 권한 정책

MVP에서는 별도 권한을 요청하지 않는다.

제외 권한:

- 카메라
- 위치
- 연락처
- 알림
- 마이크
- 사진 접근

### 11.4 빌드 산출물

- 빌드 결과물은 `.ait` 확장자를 가진 앱인토스 번들 파일이다.
- 최종 제출 전 샌드박스 앱과 Toss 앱 테스트를 수행한다.

## 13. 출시 기준

### 13.1 기능 완료 기준

- 홈 화면에서 규칙을 이해하고 테스트를 시작할 수 있다.
- 30초 테스트가 정상 진행된다.
- 문제는 매 응답 후 새로 생성된다.
- 정답 / 오답 / 반응속도가 정상 기록된다.
- 결과 화면에서 점수, 등급, 정답률, 평균 반응속도를 확인할 수 있다.
- 다시 하기가 정상 동작한다.
- 상세 분석 보상형 광고 플로우가 정상 동작한다.
- 광고 미지원 환경에서도 앱이 깨지지 않는다.

### 13.2 광고 완료 기준

- HomeScreen 배너 광고가 노출된다.
- ResultScreen 배너 광고가 노출된다.
- TestScreen에는 광고가 노출되지 않는다.
- 보상형 광고는 미리 로드된다.
- `userEarnedReward` 이벤트 발생 시에만 상세 분석이 열린다.
- 광고 실패 시 사용자에게 안내 문구가 표시된다.

### 13.3 앱인토스 테스트 기준

- 앱인토스 샌드박스 앱에서 정상 실행된다.
- Toss 앱 내부 환경에서 정상 실행된다.
- `intoss://cheonggi-baekgi-test` 스킴으로 진입 가능하다.
- 화면 이동이 Granite 라우팅 기준으로 정상 동작한다.
- `.ait` 번들 빌드가 성공한다.
