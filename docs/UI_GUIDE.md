# UI 디자인 가이드: 청기백기 색깔 테스트

## 1. UI / UX 방향

### 1.1 플랫폼

- 앱인토스 전용 React Native 미니앱
- Granite 기반 React Native 프로젝트
- 토스 앱 내부 실행 환경 기준
- 앱인토스 샌드박스 및 토스 앱 테스트 환경 기준
- 앱스토어 / 플레이스토어 직접 배포는 고려하지 않는다.
- Android / iOS 개별 앱 패키징은 고려하지 않는다.
- `.ait` 번들로 앱인토스에 제출하는 구조를 기준으로 한다.
- 토스 앱 내 미니앱 사용 흐름에 맞게 빠르고 단순한 UI를 우선한다.

---

### 1.2 디자인 방향

- 게임처럼 가볍지만, 너무 유치하지 않게 만든다.
- 토스 앱 안에서 자연스럽게 보이는 작은 테스트 도구처럼 만든다.
- 마케팅 랜딩 페이지처럼 과한 장식을 넣지 않는다.
- 색상 테스트 앱이므로 색상 대비와 가독성을 최우선으로 한다.
- 사용자는 화면을 보자마자 “무엇을 해야 하는지” 이해할 수 있어야 한다.
- 테스트 화면에서는 장식보다 문제 인식과 버튼 터치 편의성을 우선한다.
- 토스 앱 내 다른 서비스와 이질감이 너무 크지 않도록 단정한 UI를 유지한다.
- 광고 영역은 콘텐츠와 명확히 분리하되, 사용 흐름을 방해하지 않게 배치한다.

---

### 1.3 화면 톤

- MVP에서는 밝은 배경을 기본으로 한다.
- 배경은 `#F8FAFC` 또는 `#FFFFFF` 계열을 사용한다.
- 텍스트는 진한 회색 또는 검정 계열을 사용한다.
- 주요 색상은 테스트 색상 자체가 담당한다.
- 브랜드 포인트 색상은 과하게 쓰지 않는다.
- 결과 화면은 차분하지만 성취감이 느껴지도록 구성한다.
- 테스트 진행 중에는 사용자의 집중을 방해하는 색상, 장식, 애니메이션을 최소화한다.
- 테스트 색상 버튼은 명확한 라벨과 함께 제공해 색상만으로 판단하지 않도록 한다.

---

### 1.4 금지 디자인

- 글래스모피즘 사용 금지
- 보라 / 인디고 중심의 AI 느낌 금지
- 네온 글로우 애니메이션 금지
- 배경에 블러 원형 오브젝트 금지
- 그라데이션 텍스트 금지
- `Powered by AI` 같은 불필요한 배지 금지
- 과도한 캐릭터 장식 금지
- 테스트 중 화면 흔들림, 과한 파티클 효과 금지
- 주요 버튼과 광고가 너무 가까이 붙는 배치 금지
- 광고를 게임 버튼처럼 보이게 만드는 디자인 금지
- 토스 앱 기본 내비게이션과 충돌하는 커스텀 헤더 남용 금지

## 3. 타이포그래피

- 한글 가독성을 최우선으로 한다.

- 테스트 화면의 색상 단어는 매우 크게 표시한다.
- 긴 문장보다 짧은 안내 문구를 사용한다.
- 토스 앱 내부 사용성을 고려해 과도하게 작은 글씨를 피한다.

## 4. 레이아웃

### 4.1 전체 레이아웃

- 기본 좌우 여백은 `20px`로 한다.
- 화면 상단에는 충분한 여백을 둔다.
- 주요 CTA는 하단에 배치하되, 광고와 충분히 떨어뜨린다.
- 테스트 화면에서는 중앙 단어와 하단 버튼 영역을 명확히 분리한다.
- 화면 전환은 단순하게 유지한다.
- 콘텐츠는 세로 스크롤이 가능하되, TestScreen은 가능한 한 한 화면 안에서 동작하도록 한다.

---

### 4.2 Safe Area

- 토스 앱 내부 실행 환경을 고려해 Safe Area를 적용한다.
- 상단 시스템 영역과 겹치지 않도록 한다.
- 하단 광고 영역과 CTA 버튼이 겹치지 않도록 한다.
- 배너 광고가 있는 화면은 하단 여백을 충분히 확보한다.

---

### 4.3 화면별 레이아웃 요약

| 화면 | 레이아웃 방향 |
|---|---|
| HomeScreen | 설명 + 예시 + 시작 CTA + 배너 광고 |
| TestScreen | 상단 상태값 + 중앙 문제 + 하단 선택 버튼 |
| ResultScreen | 등급/점수 우선 + 지표 카드 + CTA + 배너 광고 |
| DetailResultScreen | 상세 지표 카드 + 개선 팁 + 다시 하기 CTA |

## 5. 컴포넌트 디자인

### 5.1 카드

```ts
const cardStyle = {
  backgroundColor: '#FFFFFF',
  borderRadius: 16,
  borderWidth: 1,
  borderColor: '#E5E7EB',
  padding: 20,
};
```

#### 사용 위치

- 예시 카드
- 결과 요약 카드
- 상세 분석 카드
- 안내 카드

---

### 5.2 PrimaryButton

```ts
const primaryButtonStyle = {
  height: 56,
  borderRadius: 14,
  backgroundColor: '#111827',
  alignItems: 'center',
  justifyContent: 'center',
};
```

#### 사용 위치

- 시작하기
- 다시 하기
- 광고 보고 상세 분석 보기

---

### 5.3 SecondaryButton

```ts
const secondaryButtonStyle = {
  height: 52,
  borderRadius: 14,
  backgroundColor: '#F3F4F6',
  alignItems: 'center',
  justifyContent: 'center',
};
```

#### 사용 위치

- 공유하기
- 설정
- 뒤로가기성 보조 행동

---

### 5.4 ColorChoiceButton

```ts
type ColorChoiceButtonProps = {
  label: string;
  color: string;
  textColor: string;
  onPress: () => void;
  disabled?: boolean;
};
```

#### 디자인 요구사항

- 최소 높이는 `64px` 이상으로 한다.
- 2열 그리드 형태를 기본으로 한다.
- 라벨 텍스트를 반드시 표시한다.
- 색상만으로 의미를 전달하지 않는다.
- 버튼 간 간격은 최소 `12px` 이상으로 한다.
- 테스트 중 빠르게 누를 수 있도록 터치 영역을 넓게 잡는다.

---

### 5.5 ColorWordCard

```ts
type ColorWordCardProps = {
  label: string;
  color: string;
};
```

#### 디자인 요구사항

- 중앙에 고정 배치한다.
- 텍스트는 매우 크게 표시한다.
- 배경과 충분한 대비를 확보한다.
- 문제 변경 시 레이아웃이 흔들리지 않도록 한다.
- 과한 애니메이션 없이 즉시 변경한다.

---

### 5.6 TimerBar

```ts
type TimerBarProps = {
  remainingMs: number;
  totalMs: number;
};
```

#### 디자인 요구사항

- 상단 영역에 배치한다.
- 남은 시간을 직관적으로 보여준다.
- 색상은 중립적으로 유지한다.
- 시간이 줄어들수록 길이가 줄어든다.
- 5초 이하에서는 주의 색상을 사용할 수 있다.

---

### 5.7 BannerAdSlot

앱인토스 RN 배너 광고는 `InlineAd` 컴포넌트를 기준으로 구현한다.

```tsx
import { InlineAd } from '@apps-in-toss/framework';

type BannerAdSlotProps = {
  placement: 'home_bottom' | 'result_bottom';
};
```

#### 디자인 요구사항

- 홈 화면 하단에 배치한다.
- 결과 화면 하단에 배치한다.
- 테스트 진행 화면에는 배치하지 않는다.
- 광고 영역은 주요 CTA와 충분히 분리한다.
- 광고 실패 또는 미지원 환경에서도 레이아웃이 깨지지 않아야 한다.
- 고정 배너는 높이 `96px` 기준을 고려한다.
- 스크롤 내부 광고는 콘텐츠 흐름을 방해하지 않도록 한다.

## 6. 화면 설계

### 6.1 HomeScreen

#### 목적

사용자가 테스트 규칙을 빠르게 이해하고 시작하게 한다.

#### 구성

- 앱 이름
  - `청기백기 색깔 테스트`
- 설명
  - `글자의 뜻이 아니라 실제 색깔을 고르세요.`
- 예시 카드
  - `'빨강'이라는 글자가 파란색이면 정답은 파랑입니다.`
- 시작하기 버튼
- 하단 배너 광고

#### UI 요구사항

- 앱 이름은 화면 상단에 명확하게 표시한다.
- 설명 문구는 짧고 직관적으로 작성한다.
- 예시 카드는 테스트 규칙을 바로 이해할 수 있도록 보여준다.
- 시작하기 버튼은 한 손으로 누르기 쉬운 크기로 제공한다.
- 배너 광고는 시작하기 버튼과 충분한 간격을 둔다.
- 스크롤 컨테이너 사용 시 광고 노출 측정을 고려한다.

---

### 6.2 TestScreen

#### 목적

사용자가 제한 시간 동안 색상 정답을 선택한다.

#### 구성

- 상단
  - 남은 시간
  - 현재 점수
  - TimerBar
- 중앙
  - 색상 단어
- 하단
  - 색상 선택 버튼 4개

#### UI 요구사항

- 중앙 단어는 매우 크게 표시한다.
- 단어 위치는 고정한다.
- 선택 버튼은 엄지손가락으로 누르기 쉬운 크기여야 한다.
- 버튼 간 간격을 충분히 둔다.
- 테스트 진행 중 광고는 표시하지 않는다.
- 테스트 중에는 불필요한 안내 문구를 노출하지 않는다.
- 정답 / 오답 피드백은 짧고 즉각적으로 제공한다.
- 오답 시에도 흐름이 끊기지 않도록 다음 문제로 자연스럽게 넘어간다.
- 화면 전체가 터치 실수를 유발하지 않도록 구성한다.

---

### 6.3 ResultScreen

#### 목적

테스트 결과를 간결하고 만족스럽게 보여준다.

#### 구성

- 집중력 등급
- 최종 점수
- 정답률
- 평균 반응속도
- 짧은 해석
- 다시 하기 버튼
- 상세 분석 보기 버튼
- 공유하기 버튼
- 하단 배너 광고

#### UI 요구사항

- 가장 중요한 결과인 집중력 등급과 점수를 먼저 보여준다.
- 정답률과 평균 반응속도는 카드 형태로 분리해 보여준다.
- 결과 해석은 짧고 긍정적인 문장으로 제공한다.
- 다시 하기 버튼은 가장 눈에 잘 띄는 CTA로 제공한다.
- 상세 분석 보기는 보상형 광고와 연결한다.
- 공유하기 버튼은 MVP에서 단순 텍스트 공유 방식으로 제공할 수 있다.
- 배너 광고는 결과 확인을 방해하지 않는 위치에 배치한다.

---

### 6.4 DetailResultScreen

#### 목적

보상형 광고를 시청한 사용자에게 더 자세한 결과 분석을 제공한다.

#### 구성

- 전체 결과 요약
- 정답 / 오답 개수
- 평균 반응속도
- 가장 빠른 반응속도
- 가장 느린 반응속도
- 집중력 해석 문구
- 개선 팁
- 다시 하기 버튼

#### UI 요구사항

- 상세 분석은 과도하게 복잡한 차트 없이 텍스트와 간단한 카드 중심으로 제공한다.
- 사용자가 자신의 결과를 쉽게 이해할 수 있도록 쉬운 문장으로 작성한다.
- 결과를 부정적으로 표현하지 않는다.
- “다음에는 더 좋아질 수 있다”는 긍정적인 톤을 유지한다.

## 7. 광고 UI 가이드

### 7.1 배너 광고

앱인토스 RN에서는 배너 광고를 `InlineAd` 컴포넌트로 렌더링한다.

#### 노출 위치

- HomeScreen 하단
- ResultScreen 하단

#### 미노출 위치

- TestScreen
- 테스트 준비 중 화면
- 문제 풀이 중 화면

#### UI 요구사항

- 주요 CTA 바로 아래에 붙이지 않는다.
- 버튼과 광고 사이에는 최소 `24px` 이상의 간격을 둔다.
- 광고 영역은 콘텐츠와 시각적으로 분리한다.
- 광고 로딩 실패 시 빈 공간 때문에 UI가 어색해지지 않도록 한다.
- 미지원 환경에서는 광고 영역을 숨기거나 대체 여백을 최소화한다.

---

### 7.2 보상형 광고

보상형 광고는 `상세 분석 보기` 버튼과 연결한다.

#### 버튼 문구

```txt
광고 보고 상세 분석 보기
```

#### 안내 문구

```txt
광고를 보면 정답률, 반응속도, 개선 팁을 확인할 수 있어요.
```

#### UI 요구사항

- 광고를 보기 전에 사용자가 받을 보상을 명확히 설명한다.
- 광고 시청 실패 시 상세 분석 화면으로 이동하지 않는다.
- 광고 완료 이벤트가 확인된 경우에만 상세 분석 화면으로 이동한다.
- 광고 로딩 중에는 중복 클릭을 막는다.

## 8. 애니메이션 가이드

### 8.1 허용 애니메이션

- 화면 전환 fade
- 정답 시 짧은 체크 피드백
- 오답 시 짧은 흔들림 또는 색상 피드백
- TimerBar 감소 애니메이션
- 결과 등급 표시 시 짧은 scale-in

### 8.2 금지 애니메이션

- 네온 글로우
- 배경 파티클
- 계속 움직이는 장식 요소
- 테스트 중 단어가 크게 움직이는 효과
- 광고 CTA를 과하게 흔드는 효과
- 사용자의 집중을 방해하는 반복 애니메이션

## 9. 접근성 기본 가이드

### 9.1 색상 접근성

- 색상만으로 정답을 판단하게 하지 않는다.
- 색상 버튼에는 반드시 라벨 텍스트를 표시한다.
- 노랑 버튼처럼 밝은 색상은 검정 텍스트를 사용한다.
- 배경과 텍스트 간 대비를 충분히 확보한다.

---

### 9.2 터치 접근성

- 주요 버튼 높이는 최소 `52px` 이상으로 한다.
- 색상 선택 버튼 높이는 최소 `64px` 이상으로 한다.
- 버튼 간 간격은 최소 `12px` 이상으로 한다.
- 테스트 화면 하단 선택 영역은 한 손 조작을 고려한다.

---

### 9.3 문구 접근성

- 어려운 용어를 피한다.
- 규칙 설명은 2문장 이내로 제공한다.
- 오류 메시지는 사용자 행동을 안내하는 방식으로 작성한다.
